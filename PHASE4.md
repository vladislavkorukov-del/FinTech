# Phase 4 · build 142

Продолжение build141 в существующей архитектуре. Главное меню, финансовые
экраны, голосовой парсер и модельные ревизии сохранены. Qwen необязательна,
выключена по умолчанию; веса отдельно, облачного AI нет.

## Загрузка и состояние

`local_model/model_download.dart` начинает каждую попытку с официального
HTTPS resolve repo/revision/path. Redirect ограничен; TLS не отключается,
секреты не пересылаются на чужой host. Отдельные connect/idle timeout,
identity encoding, ограниченный exponential backoff/jitter, Retry-After,
классификация ошибок. CDN403 допускает новый resolve, не доказывает истечение URL.

Файлы пишутся последовательно на диск, без буфера размера модели. `.part` и
метаданные связывают ревизию, файл, размер, SHA и HTTP validators. Resume
проверяет смещение Content-Range, 200 перезапускает файл, 416 проверяет
целостность/безопасно перезапускает. Прогресс считает записанные байты.
100%/ready только после SHA всех обязательных файлов. Проверка больших файлов
в isolate. Активация пакета атомарна; прежний рабочий пакет сохраняется.

При уходе в фон загрузка приостанавливается. После перезапуска доступны
«Продолжить»/удаление незавершённого пакета; старые build141 `.part` распознаются.
Фонового Android download worker нет. Короткая inline-ошибка на экране модели;
общий `showError` тоже очищает исключения. Диагностика хранит этап, код,
байты, попытки, HTTP status и host без подписанного query/Authorization.

Включение проверяет настоящую инициализацию runtime. Неудача не оставляет
включённый переключатель. После освобождения runtime намерение использовать
установленную модель сохраняется, статус загрузки runtime показывается отдельно.

## Диалог и команды

В существующем чате доступны `open_screen`, `show_entries`, `set_theme`,
`create_entry`, `edit_last_category`, `plan_debts`, `review_week`, `assistant_memory`.
Реестр содержит риск/необходимые данные. Модель предлагает только whitelist JSON;
схема, текущие объекты, доверенное намерение и fingerprint проверяются кодом.
Потоковый JSON не исполняется. Голос переиспользует прежние обработчики.

«Добавь расход 850 на продукты» → «Это было вчера» → «Спиши с наличных»
уточняет один черновик. Исправление суммы, отрицание, смена темы и TTL5min
обрабатываются отдельно. Явная дата привязана к моменту её сообщения.
Подтверждение не восстанавливается после перезапуска. Черновик и до100 consumed
request IDs сохраняются в прежнем JSON истории. Перед запуском действия
подтверждение должно сохраниться; при сбое записи действие не начинается.
Стабильный `assistant:<draftId>` предотвращает повторную запись одного черновика.
Даже после подтверждения расход открывает штатную форму: сохранить должен пользователь.

## Платежи

Открыть: настройки Finora AI → «План погашения», либо запрос в чате
«Посчитай все мои долги, распредели и запланируй платежи на каждую неделю».
Без Qwen этот запрос тоже работает.

Пользователь выбирает источник, общий бюджет на горизонт7–90дней, резерв и
день группировки недели. Код берёт актуальные остатки, реальные даты известных
поступлений и обязательств, договорные минимумы и существующий PaymentPlan.
Первая версия сохраняет договорные даты и группирует выплаты по неделям,
не делит бюджет на4 и не обещает оптимальный график/досрочное погашение.
День планирования задаёт начало группировки, не переносит срок оплаты.

Долги и суммы к получению разделены; валюты не конвертируются и не складываются
в общий денежный итог. Суммы к получению не считаются гарантированным поступлением.
Процентные расчёты наследуют доступные условия PaymentPlan и помечаются прогнозом;
неизвестные комиссии не выдумываются. Для неполных условий и отрицательной кредитной
карты без связи с обязательством нужна проверка условий, успешное сохранение блокируется.
Не хватает денег/бюджета/резерва — показываются сумма и дата нехватки.

После просмотра дат, источника, ожидаемых остатков и предположений пользователь
отдельно подтверждает запись. Один `FinanceController.mutate` сохраняет pending
FinanceEntry в существующую БД/календарь. Никакого банковского перевода нет.
До posted баланс, долг и аналитика не меняются. Повторное применение плана
идемпотентно, финансовый fingerprint защищает от устаревшего расчёта.
Пересчёт заменяет только свои pending, сохраняя проведённые/отменённые записи;
экран показывает старое/новое число выплат и общую сумму.

Связь: `recurringRuleId`, `planningBatchId`, `plannedDueDate`; nullable миграция
schema7→8. Частичная выплата уменьшает только фактический остаток; дата договора
переходит после покрытия платежа. Уменьшение/отмена/удаление posted восстанавливает
неоплаченный срок и остаток. Подтверждение проверяет снимок правила/плановой строки,
срок и ID подтверждения атомарно. Архивный источник не используется.
Штатные напоминания показывают остаток текущей частично оплаченной выплаты.
Настройка напоминаний включает существующие правила; глобальное разрешение остаётся
добровольным. Отдельного календаря/планировщика уведомлений нет.

## Память и сценарии

Настройки Finora AI → «Память и сценарии»: основной счёт, день планирования,
краткий/подробный отчёт, параметры погашения. Сохранение только явно пользователем,
не по догадке Qwen. Можно просмотреть, изменить, удалить.

Сценарий: название, версия, время изменения, необходимые данные и typed steps
(summary/upcomingPayments/debtPlan/showEntries) с whitelist параметрами. Без кода,
SQL и автоматического расписания. После подтверждённого недельного разбора команда
«Сохрани такой недельный разбор» предлагает сохранение. Планировщик также сохраняет
параметры как сценарий. Каждый запуск получает текущую БД и дату, не старый ответ.
Для шагов просмотра операций открывается штатный фильтр; сохранение плана требует
нового расчёта/подтверждения. Краткий список ближайших платежей показывает следующий
срок каждого правила в выбранном горизонте, не все повторы.

Memory schema3→4 сохраняет старые merchants, corrections и голоса; атомарные
serialized writes. Сброс обучения не удаляет подтверждённые настройки/сценарии.
Они включены в существующий JSON backup памяти. Повреждённая память не перезаписывается;
её формат проверяется до импорта финансов. Финансовый импорт и отдельный JSON памяти
не составляют единую файловую транзакцию. История чата отдельно и в старый финансовый
backup не входит. Удаление/отключение модели эти данные не затрагивает.
