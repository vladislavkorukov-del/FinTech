# Локальная безопасность и уведомления

Finance не отправляет финансовые данные на сервер. Release-манифест не запрашивает интернет. Данные находятся в приватном каталоге приложения Android. Автоматические Android Backup и перенос данных отключены; пользователь создаёт резервную копию явно.

## Блокировка приложения

PIN содержит 4–6 цифр. Он не хранится открытым: используется PBKDF2-HMAC-SHA256 (210 000 итераций, случайная 32-байтная соль), сравнение без раннего выхода, Android EncryptedSharedPreferences через Flutter Secure Storage. После пяти ошибок включается задержка 30 секунд с удвоением до одного часа. Счётчик сохраняется между перезапусками. Биометрия использует Android BiometricPrompt через `local_auth`; PIN остаётся способом восстановления доступа. Ошибка или отмена биометрии не открывает приложение.

Это локальный экран блокировки, а не шифрование SQLite. Защита данных на устройстве опирается на Android sandbox и шифрование устройства. Root-доступ, изменённая ОС и извлечение расшифрованной базы из работающего процесса лежат вне этой модели защиты. PIN нельзя восстановить по почте: серверной учётной записи нет. Экспорт JSON/CSV и ручная резервная копия не зашифрованы — храните их в доверенном месте. PIN и биометрические настройки в экспорт не включаются.

Начиная с версии1.1 снимки экрана разрешены по запросу пользователя: MainActivity очищает `FLAG_SECURE`. PIN/биометрия и блокировка всех маршрутов сохраняются. В версии 1.2 кнопка глаза и функция скрытия сумм удалены по запросу пользователя.

## Чеки и банковские скриншоты (1.4)

Изображение из галереи/камеры/Android Share копируется неизменённым в приватный каталог приложения. Распознавание Tesseract выполняется локально; модели включены в APK и проверяются по SHA-256. OCR не имеет сетевого fallback и не записывает операции. Пользователь проверяет черновик и явно сохраняет его. PIN закрывает весь Navigator, включая черновик распознанного изображения.

Отменённые несохранённые OCR-копии очищаются; сохранённый снимок остаётся вложением операции. Ручные JSON-резервные копии могут содержать изображение и распознанные поля, поэтому к ним применяются те же правила хранения, что к другим финансовым данным. Снимки экрана разрешены по прежнему запросу пользователя.

## Уведомления

Уведомления для нового профиля выключены; старый сохранённый выбор сохраняется. Разрешение Android запрашивается по явному включению. У регулярного платежа свой переключатель, время и опережение 0/1/3/7 дней. Уведомление включает название, сумму, валюту и дату оплаты. Видимость Android — `private`; содержание на заблокированном экране зависит от настроек устройства. Бюджеты уведомляют на 90% и 100% лимита; достигнутые цели уведомляют один раз. Подробности — [NOTIFICATIONS.md](NOTIFICATIONS.md).

Доставка использует неточные системные alarm: Android может задерживать её в Doze или при ограничении батареи. Разрешение на exact alarms не требуется. Получатели `BOOT_COMPLETED` восстанавливают запланированные уведомления после перезагрузки. При смене часового пояса заново откройте приложение для перепланирования.

Автоматические операции создаются обработчиком регулярных правил при запуске/возобновлении приложения; уведомление само по себе не выполняет финансовую операцию. Фоновая синхронизация и выполнение операций при закрытом приложении не заявлены.

## Android-сборка

Название на устройстве — Finance. Application ID сохранён `com.finora.fintech` для обновления без потери данных; минимум Android API 24. Gradle Wrapper 9.3.1 проверяет SHA-256 официального дистрибутива; JAR wrapper также сверён с официальной контрольной суммой. Android Gradle Plugin 9.1.0, Kotlin 2.4.0 и флаги совместимости `android.newDsl=false`, `android.builtInKotlin=false` соответствуют шаблонам Flutter 3.47.9. Release-сборка не подписывается debug-ключом: перед распространением подготовьте собственную release-подпись, имя пакета и политику конфиденциальности. Хранилища ключей и `key.properties` исключены из Git.

Нативные разрешения, биометрия, восстановление уведомлений после перезагрузки, смена часового пояса и ограничения батареи требуют проверки на реальном Android-устройстве. Успех анализа Dart или unit-тестов не заменяет эти проверки.

Для подписанного release создайте локальный `android/key.properties` с полями `storeFile`, `storePassword`, `keyAlias`, `keyPassword`. Путь `storeFile` разрешается относительно каталога `android`, либо может быть абсолютным. Заполняйте пароли локально, не в чате и не в Git. Затем выполните `flutter build appbundle --release`. Неполный файл настроек подписи останавливает сборку; при отсутствии файла release остаётся неподписанным. Debug-сборку можно проверить командой `flutter build apk --debug`.
