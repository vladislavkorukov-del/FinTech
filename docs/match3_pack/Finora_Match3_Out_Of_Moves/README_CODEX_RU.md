# FINORA — Поток: «Закончились ходы»

15 отдельных PNG: 6 новых компонентов окна и 9 переиспользованных утверждённых элементов (две основы кнопок, надпись «К уровням» и шесть фишек целей). Каждый оригинал создан отдельно; графика не вырезана из общего макета.
Надписи отделены от основ кнопок. Количество оставшихся целей выводится живым текстом.

## Задание для Codex
Встроить окно в существующую Flutter-игру FINORA — Поток. Перед изменениями изучить игровой цикл, окончание каскадов, условие победы, оставшиеся ходы/цели и существующий механизм дополнительных ходов.

1. Разместить компоненты в assets/finora/match3/out_of_moves/ и зарегистрировать папку в pubspec.yaml. Для общих ассетов можно использовать уже существующие пути проекта.
2. Показывать окно, когда ходы исчерпаны, все каскады и отложенные действия завершены, а цели ещё не выполнены. Если на последнем ходу цели выполнены, показать победу. Обеспечить только одно активное окно завершения попытки.
3. Заблокировать взаимодействие с игровым полем и панелями. Сохранить текущие поле, очки, цели и бустеры под затемнением. Само затемнение рисовать средствами Flutter: ориентир #4B2346 с непрозрачностью около 0.48.
4. Карточку центрировать в SafeArea. Начальная ширина около 72–80% полезной ширины телефона. Порядок: заголовок → «Осталось собрать» → фишки оставшихся целей и количества → мятная «Ещё 5 ходов» → лавандовая «Заново» → жемчужная «К уровням».
5. Список иконок и оставшиеся количества брать из состояния текущего уровня. Показанные на референсе 5 монет и 3 щита — пример, не постоянные значения. Остаток ограничивать снизу нулём; выполненные цели скрывать или отмечать по принятой в игре схеме.
6. Количества выводить отдельными Flutter Text. Для всех целей использовать один размер, вес и цвет цифр. Ориентир цвета #4B1038, жирный шрифт проекта со стабильной шириной цифр. Выравнивать иконки по визуальному размеру и числа по общей линии.
7. Адаптировать расположение под фактическое число целей и узкий экран. При нескольких целях допускается компактная сетка с сохранением читаемости и доступности трёх действий.
8. Фоны и надписи кнопок объединить в единую зону нажатия через Stack или существующий UI-компонент. Все три кнопки одинаковой ширины; текст на них одного кегля и веса. Не масштабировать короткое «Заново» к ширине длинной надписи.
9. «Ещё 5 ходов» подключить к существующим правилам получения дополнительных ходов: проверке доступности, нужным условиям и успешному результату операции. Начислить 5 ходов ровно один раз после успеха. Затем закрыть окно и продолжить ту же попытку, сохранив поле, очки и прогресс целей. При отмене или ошибке оставить попытку в корректном состоянии, дополнительные ходы не начислять.
10. Надпись «Ещё 5 ходов» содержит фиксированное число 5. Если реальное предложение проекта выдаёт другое число, отображать точную надпись через Flutter Text в том же стиле либо подготовить новый текстовый ассет. Условия предложения, включая стоимость при её наличии, брать из конфигурации игры и показывать пользователю в существующем сценарии получения. Этот графический комплект не задаёт цену, источник награды или лимиты продолжений.
11. «Заново» вызывает существующий сценарий повторного запуска уровня. «К уровням» — действующий переход к выбору уровней. Сохранить текущие правила расходования ресурсов и подтверждений проекта.
12. Во время получения ходов и навигации блокировать повторное нажатие. Для недоступных/занятых действий использовать состояния UI проекта; отдельная растровая графика для этого не требуется.
13. Для всех кнопок обеспечить раздельные зоны нажатия минимум 48×48 логических пикселей и семантические подписи. Системную кнопку назад и касание вне окна согласовать с текущей логикой завершения попытки, исключив ввод на поле через окно.
14. Проверить: незавершённые цели при нуле ходов, победу последним ходом, разные числа целей, получение дополнительных ходов, повторное открытие, отмену/ошибку получения, повторные нажатия и навигацию на узком телефоне.

## Размеры и баланс надписей
manifest.json содержит фактические размеры PNG, диапазон альфа-канала и visible_bounds_alpha128 — границы основного объекта (left, top, right, bottom; right/bottom не включены). Исходники сохраняют прозрачные поля, особенно у кнопок и текста.
При размещении учитывать видимые границы. Можно подготовить обрезанные производные файлы из каждого отдельного оригинала с запасом для сглаживания. Не извлекать графику из preview и не растягивать буквы/фишки непропорционально.

У трёх надписей кнопок есть typography.capital_height_px — высота первой заглавной буквы на экспортированном изображении:
- «Ещё 5 ходов»: 100 px;
- «Заново»: 151 px;
- «К уровням»: 116 px.
Для одинакового кегля масштаб = desiredCapitalHeight / capital_height_px. В контрольной сборке при ширине карточки около 980 px целевая высота заглавной буквы 42 px. Это относительный графический ориентир, не размер текста в логических пикселях телефона.
Длинные надписи не растягивать до полной ширины кнопки. Заголовок уже содержит две строки одинакового кегля.
