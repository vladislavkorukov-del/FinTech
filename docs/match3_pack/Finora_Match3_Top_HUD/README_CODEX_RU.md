# FINORA — Поток: верхняя панель
В комплекте 9 отдельных PNG с настоящим альфа-каналом. Каждый элемент сгенерирован самостоятельно, а не вырезан из общего макета. В папке preview находится композиционный референс; его не использовать вместо работающего интерфейса.

## Задание для Codex
Встроить эти изображения в существующий Flutter-экран Match-3. Сохранить действующую игровую логику и утверждённые поле, фишки, жемчужно-золотую рамку. До изменений изучить структуру проекта и найти существующее состояние игры.

1. Разместить файлы в assets/finora/match3/hud/ и зарегистрировать папку в pubspec.yaml по правилам проекта.
2. Собрать адаптивный HUD в SafeArea, над полем. Верхняя строка: надпись уровня с динамическим номером и пауза справа. Следующая строка: карточка ходов слева, более широкая карточка целей справа. Нижняя строка: счёт и шкала с тремя звёздами.
3. Цифры ходов, уровня, счёта и оставшегося количества целей выводить живыми Flutter Text. Не запекать их в изображения. Примерные 12, 24, 20, 15, 1250 на референсе не являются значениями для всех уровней.
4. Надписи «ХОДЫ» и «ЦЕЛИ» уже находятся на своих карточках: не дублировать их текстом. Для «Уровень» использовать отдельный PNG и размещать динамический номер рядом. Для accessibility задавать текстовое описание, исключив двойное озвучивание.
5. Иконки целей брать из уже утверждённого набора match3_coin.png, match3_wallet.png, match3_goal.png, match3_shield.png, match3_receipt.png, match3_chart.png. Этот комплект их не дублирует. Вид целей и число определяются уровнем. Отображать оставшееся количество, не допускать отрицательных значений.
6. Цвет динамических цифр — глубокий сливовый, ориентир #4B1038. Использовать подходящий жирный шрифт проекта с поддержкой кириллицы и стабильной шириной цифр. Обеспечить читабельность без выхода за карточки.
7. Заполнение шкалы — отдельный спрайт полного размера. Разместить его в углублении пустого трека. При изменении прогресса обрезать слева направо через ClipRect/маску, сохраняя исходную полную ширину изображения: не сжимать весь рисунок до текущего процента. Ограничить значение диапазоном 0..1; при нуле полностью скрыть заполнение.
8. Пороговые значения трёх звёзд брать из конфигурации уровня. Положение звезды = её порог / максимум шкалы. Полученную звезду показывать золотой, остальные — лавандовыми. Не привязывать их к случайным очкам из референса.
9. Пауза должна вызывать существующую паузу игры и останавливать игровой процесс согласно текущей архитектуре. Зона нажатия минимум 48×48 логических пикселей, описание «Пауза».
10. Проверить узкие и широкие телефоны, увеличенный системный шрифт, длинные числа и разные наборы целей. Не перекрывать игровое поле. При нехватке места адаптировать раскладку.

## Размеры и прозрачные поля
manifest.json содержит настоящие размеры каждого PNG и visible_bounds_alpha128 — границы основного видимого объекта в пикселях (left, top, right, bottom; правая и нижняя границы не включены). Сами исходники не обрезаны: у длинных плашек и шкал заметные прозрачные поля сверху и снизу.

Для точной раскладки учитывать видимые границы, а не только размеры всего файла. Можно подготовить производные спрайты с обрезкой прозрачных полей каждого отдельного оригинала либо отрисовывать нужную область исходника. При обрезке оставить небольшой запас для сглаживания. Не вырезать элементы из preview. Не растягивать звёзды и кнопку непропорционально; у звёзд выравнивать видимые центры между состояниями.

Начальные пропорции: карточка ходов около 28% полезной ширины ряда; цели около 69%; зазор около 3%. Сохранять пропорции видимых частей карточек, согласовывая высоту ряда. Верхний заголовок и пауза должны оставлять место друг другу. Финальные размеры подстроить под существующий экран.

## Проверки
Проверены PNG RGBA, наличие полностью прозрачных и полностью непрозрачных пикселей, текстовые подписи и внешний вид отдельных компонентов на светлом лавандовом фоне. Работающий Flutter-экран этим архивом не создан и в приложении ещё не проверен.
