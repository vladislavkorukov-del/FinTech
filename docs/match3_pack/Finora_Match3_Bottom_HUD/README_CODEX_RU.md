# FINORA — Поток: нижняя панель усилителей

Комплект: 8 самостоятельных PNG с настоящим альфа-каналом, макет из этих элементов и утверждённый референс. Каждый компонент сгенерирован отдельно. Рисунки не вырезаны из общего макета.

## Задание для Codex
Встроить нижнюю панель в существующую Flutter-игру FINORA — Поток. Сначала изучить устройство экрана, состояние игры, состояние инвентаря и действующие обработчики усилителей. Использовать существующие правила и баланс игры.

1. Скопировать PNG в assets/finora/match3/boosters/ и зарегистрировать папку в pubspec.yaml по правилам проекта.
2. Разместить панель под игровым полем в нижней SafeArea, сохранив утверждённые фон, поле, рамку и верхний HUD.
3. Собрать основу и четыре ячейки. Порядок слева направо: молоток, бомба, перемешивание, +5 ходов.
4. В каждой ячейке разместить значок в верхней части, плашку запаса внизу слева, кнопку «+» внизу справа. Размеры значков подбирать по визуальной массе: открытый силуэт стрелок допускает большую ширину. Не деформировать значки, круглую кнопку и плашки.
5. Запас брать из состояния инвентаря и выводить отдельным Flutter Text поверх пустой плашки. Примерные 3, 2, 1, 0 на превью не фиксировать в игре. Цвет цифр — глубокий сливовый, ориентир #4B1038, жирный шрифт с устойчивой шириной цифр.
6. Надпись «+5» уже находится на иконке часов и обозначает пять дополнительных ХОДОВ, а не секунды. Это отдельная сущность от счётчика количества усилителей. Не накладывать повторную надпись на рисунок.
7. Нажатие значка должно вызывать существующий сценарий выбора или применения соответствующего усилителя. Учитывать текущую фазу игры, наличие запаса, состояние анимаций и выбор цели. Списывать запас в момент успешного применения по правилам проекта.
8. Кнопку «+» связать с существующим окном получения или пополнения именно этого усилителя. Если сценарий пока отсутствует, сделать соответствующий callback и отдельно обозначить незавершённое подключение. Одного факта нажатия «+» недостаточно для выдачи предмета.
9. При нулевом запасе сохранить читаемость рисунка и кнопки «+». Использовать существующее поведение для недоступного усилителя.
10. Для активной ячейки добавить лёгкое визуальное выделение средствами Flutter. Состояния выбора и блокировки не запечены в этот набор. Семантические названия: «Молоток», «Бомба», «Перемешивание», «Пять дополнительных ходов»; озвучивать запас.
11. Тап-зоны кнопок — минимум 48×48 логических пикселей. Визуальный размер может быть меньше, но соседние hit-зоны должны оставаться раздельными. Проверить их на узком телефоне. При нехватке места увеличивать высоту панели или менять внутреннюю раскладку.
12. Проверить разные размеры телефонов, нижние системные отступы, нулевой и многозначный запас, повторные нажатия и блокировку во время каскада. Игровое поле и нижний интерфейс не должны перекрываться.

## Прозрачные поля и размеры
manifest.json содержит фактические размеры файлов и visible_bounds_alpha128 — границы основного объекта в пикселях (left, top, right, bottom; right и bottom не включены). Исходники сохранены с прозрачными полями. Для точной раскладки ориентироваться на видимую область, а не на весь холст.

Можно подготовить обрезанные производные изображения из каждого отдельного PNG, сохранив запас на сглаживание. При масштабировании сохранять пропорции и центр видимого объекта. Не извлекать графику из preview. Для адаптации ширины основы при необходимости использовать корректную девятисегментную растяжку с сохранением скруглений.

## Превью и проверка

preview/Bottom_HUD_Assembled_Review.png — контрольная композиция, собранная именно из восьми отдельных компонентов. Цифры здесь приведены для демонстрации.
Проверены формат RGBA, диапазон альфа-канала 0..255 у всех восьми PNG и сочетаемость на контрольном макете. Flutter-интеграция и игровая логика этим архивом не выполнены и в приложении ещё не проверены.
