# Подключить графику препятствий FINORA — Поток

Изучи текущую модель клетки, сущности фишки, препятствия, обработку совпадений и усилителей. Этот пакет добавляет графику. Он не задаёт новый баланс и не требует заменять уже существующие правила игры.

## Ассеты

Импортируй шесть PNG из `png/`, зарегистрируй каталог в `pubspec.yaml`. Каждый PNG имеет полный холст 1024×1024 с центром [0.5, 0.5]. На игровом поле оба состояния одного препятствия всегда получают одинаковые позицию, квадрат отображения и масштаб.

Не обрезай состояния независимо по непрозрачным границам и не подгоняй каждое через собственный tight bounds: это создаст скачок размера при повреждении. В `manifest.json` границы нужны для диагностики, а не для изменения геометрии каждого кадра. Отрисовывай полный PNG с сохранением соотношения 1:1.

## Готовые фишки переиспользовать

Все шесть прежних фишек находятся в ранее выданном `Finora_Match3_6_Tiles_1024_PNG.zip`. Точные пути внутри старого архива и относительные пути к исходным PNG перечислены в `REUSED_PIECES.json`:

- `match3_coin.png`
- `match3_wallet.png`
- `match3_goal.png`
- `match3_shield.png`
- `match3_receipt.png`
- `match3_chart.png`

Сначала найди уже импортированный asset path по имени в проекте и используй его. Если набора нет, импортируй старые PNG из указанного архива. Не генерируй замену и не извлекай фишки из превью препятствий.

## Порядок слоёв

1. Существующая подложка клетки.
2. Существующая фишка, когда в клетке она есть.
3. Лёд или цепи как отдельный слой поверх фишки.
4. Короткий эффект удара/снятия, если он уже реализован.

Для ящика рисуй его отдельным объектом в клетке согласно модели блокера. Если модель не предусматривает фишку под ящиком, не создавай её искусственно ради графики. Не рисуй ледяную подложку под обычными клетками.

Прозрачность льда уже находится в PNG. Не нужно заливать его центр голубым цветом, делать весь оверлей непрозрачным или добавлять общий светящийся прямоугольник. Цепи также имеют прозрачные отверстия между звеньями.

## Выбор состояния

В `obstacle_render_map.json` указана демонстрационная схема для двух визуальных стадий: целое → повреждённое → отсутствие слоя. При текущей прочности 2 можно использовать целое состояние, при 1 — повреждённое, при 0 — убрать препятствие. Если в игре другая система прочности, адаптируй только сопоставление состояния, не меняя баланс автоматически.

У повреждённых цепей остаётся одна диагональ, у льда — сколы и трещины, у ящика — сломанная передняя планка и расколотые доски. Повреждённые картинки не являются кадрами анимации разрушения. Картинка «пусто» не нужна: удаляется слой препятствия.

Переход выполняй в том же квадрате клетки. Допустим короткий shake или вспышка существующей системой эффектов. Для редуцированных анимаций переключай состояние сразу. При CrossFade не допусти изменения размера и положения underlying piece; в короткий переход два слоя могут дать временное усиление непрозрачности.

## Механика и цели

Правила снятия льда, фиксации цепями, урона ящику от соседних совпадений и воздействия усилителей бери из игровых требований/текущего кода. Если таких правил ещё нет, реализация механики — отдельная задача; сами PNG её не определяют.

Не уменьшай прочность повторно из-за одного и того же события повреждения. Снятие оверлея должно сохранять идентификатор и тип находящейся под ним фишки. Освобождение клетки ящика должно использовать обычный механизм заполнения поля, если он предусмотрен правилами. Цель уровня учитывается по фактическому снятию препятствия, а не по простому показу повреждённой картинки.

Для значка цели в верхней панели или окне старта сначала используй уменьшенный целый спрайт того же препятствия. Не перерисовывай отдельную иконку без необходимости. Для льда в миниатюре можно наложить готовую фишку под тот же оверлей программно, если без неё материал плохо читается; слои остаются раздельными.

## Проверки после интеграции

Сравни оба состояния на светлой и тёмной клетке, поверх каждого типа фишек и при 64×64. Проверь одинаковые масштаб и центр при переключении, исчезновение без остаточной подложки, сохранение фишки под снятым оверлеем, урон усилителями по существующим правилам, счётчик целей и корректное заполнение освобождённой клетки. Проверь отсутствие цветной каймы на целевом устройстве и DPR. Артефакты в превью не должны заменять исходные PNG.

В пакете выполнена проверка изображений и технических композиций. Поведение игрового кода и производительность Flutter нужно проверить после подключения в реальный проект.
