# FINORA — Поток: окно победы

11 отдельных PNG: 8 новых компонентов окна и 3 ранее утверждённых элемента (золотая/лавандовая звезда и монета). Каждый оригинал создан отдельно, без нарезки общего коллажа. Надписи отделены от основ кнопок для точной настройки размеров текста.

## Задание для Codex
Встроить окно победы в существующую Flutter-игру FINORA — Поток. Перед изменениями изучить финализацию уровня, подсчёт очков/звёзд, начисление награды, сохранение прогресса и переходы между уровнями.

1. Разместить PNG в assets/finora/match3/victory/ и зарегистрировать папку в pubspec.yaml.
2. Открывать окно после успешного завершения уровня, когда разрешены необходимые каскады/финальные действия по текущим правилам. Состояние результата формируется игровой логикой, а не рисунком.
3. Заблокировать взаимодействие с полем и нижней панелью. Под окном сохранить текущий игровой экран. Затемнение рисовать Flutter-слоем: ориентир #4B2346 с непрозрачностью около 0.48. Растровый фон с макета не использовать вместо работающей игры.
4. Порядок содержимого: заголовок → три места для звёзд, центральная немного выше/крупнее → «Очки» и результат → «Награда», монета и величина награды → мятная «Дальше» → жемчужная «К уровням».
5. Начальная ширина карточки около 72–80% полезной ширины телефона. Центрировать в SafeArea. На небольших экранах адаптировать интервалы/высоту, сохраняя читаемость и доступность действий.
6. Три звезды отображать отдельными спрайтами: earned для полученных, empty для остальных. Количество брать из результата уровня, не фиксировать три звезды из референса. Центрировать по видимым границам каждого состояния; не допускать скачков при замене спрайта.
7. Очки и награду выводить отдельными Flutter Text с живыми значениями. Значения 4 250 и +100 на макете — только примеры. Использовать один размер/вес цифр для обеих величин, поддержать большие числа и разделители разрядов. Цвет ориентир #4B1038, подходящий жирный шрифт проекта.
8. Прогресс, открытие следующего уровня и начисление награды должны использовать существующий механизм финализации результата. Не начислять награду повторно при каждом build, повторном открытии диалога или нажатии кнопки. Сохранить правила повторного прохождения и выдачи наград проекта.
9. «Дальше» переводит к следующему доступному уровню после фиксации результата. Для последнего доступного уровня использовать действующее поведение проекта. «К уровням» открывает существующий выбор уровней.
10. Фоны кнопок и надписи — отдельные изображения, объединить их внутри одной зоны нажатия. Семантические подписи задавать для всей кнопки. Для титула и статических подписей не добавлять поверх вторую видимую надпись.
11. Кнопки должны иметь раздельные зоны нажатия минимум 48×48 логических пикселей и достаточные отступы. Переходы защищать от повторного быстрого нажатия.
12. Допустима лёгкая последовательная анимация появления карточки, звёзд и результатов средствами Flutter. Поддержать настройки анимаций проекта; отдельная покадровая графика этим комплектом не требуется.
13. Проверить варианты результата на 1/2/3 звезды, нулевую и большую награду, большие очки, повторное открытие, навигацию и сохранение результата. Проверить узкий экран и SafeArea.

## Баланс типографики
Не масштабировать все текстовые PNG к одинаковой ширине: длинные слова станут мельче коротких. Сохранять пропорции и сопоставлять размер букв.

manifest.json содержит typography-метрики в пикселях экспортированного PNG:
- Для «Очки»: capital_height_px = 182; для «Награда»: 156. Чтобы высота заглавной буквы была одинаковой, масштабировать каждую надпись как desiredCapitalHeight / capital_height_px.
- Для «Дальше»: lowercase_x_height_px = 105; для «К уровням»: 86. Масштабировать как desiredXHeight / lowercase_x_height_px, чтобы строчные буквы обеих кнопок имели одинаковый размер. Разная полная высота строки естественна из-за выносных элементов букв.
- На контрольной сборке ширина карточки около 980 px; заглавная буква подписей около 34 px, высота строчных букв надписей кнопок около 40 px. Это относительные ориентиры, не размеры в логических пикселях телефона.
- Оба динамических числа использовать в одном кегле и весе. Заголовок — один двухстрочный PNG с уже согласованными строками.

## Размеры и прозрачность
Исходники экспортированы с сохранением пропорций и альфа-канала. Карточка 1024×1536 px; текст и основы кнопок — до 1024 px по длинной стороне; звёзды и монета — 512×512 px.
manifest.json содержит реальные размеры и visible_bounds_alpha128 (left, top, right, bottom; right и bottom не включены). Это границы основного видимого объекта. Полные PNG имеют прозрачные поля, особенно у кнопок и надписей.
Учитывать эти поля при размещении; при необходимости подготовить производные спрайты с обрезкой каждого отдельного оригинала, оставив запас на сглаживание. Не извлекать ассеты из preview. Для иконок, звёзд и букв сохранять пропорции.
