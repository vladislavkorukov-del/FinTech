# Finora AI — локальный аналитический модуль

Гибридный «интеллект» Finora: правила, статистика, персональная память и
компактная локальная ML-модель. Большая LLM не используется. Всё считается
на телефоне, без интернета. Голосовой помощник не затронут.

Главный принцип: **сначала движки считают факты → потом слой ответов
превращает их в короткий текст**. Слой ответов не может изменить ни одного
числа; если данных мало, он прямо об этом говорит. Без слоя ответов те же
факты показывает обычный UI (карточка прогноза, список инсайтов).

Соответствие требуемым движкам: InsightEngine, ForecastEngine,

NaturalLanguageResponseLayer (`ResponseLayer`).

### Поток вопроса

```
вопрос → IntentParser → нужный движок (через FinoraAiSnapshot)
       → структурированный результат → ResponseLayer → короткий ответ
```

Пример: «Почему я трачу больше?» → `MonthComparisonEngine` (те же дни
прошлого периода, разница по категориям) → `ResponseLayer.whySpendingMore`
цитирует `drivers.first.difference` без пересчёта.

### Встраивание в приложение (минимальное)

- `FinanceController.saveEntry` → `FinoraAi.observeSave` (подтверждение или
  исправление категории); `resetAll` очищает память.
- Редактор операции: для неизвестного магазина категория подставляется,
  если уверенность ≥ 60% (только когда пользователь её не выбрал сам).
- `main()` загружает модель и память в фоне.
- Один пункт в «Ещё» → «Финора · Анализ». Нижнее меню и навигация не менялись.

## 3. Движки — как считают

- **Сравнение месяцев**: текущий период до сегодня против тех же N дней
  прошлого периода; «драйвер» — изменение категории ≥ 500 ₽. Нужно ≥ 3
  операций в прошлом периоде, иначе `Insufficient`.
- **«Больше обычного»**: траты категории сейчас против медианы 2–3 прошлых
  периодов, приведённой к прошедшей доле месяца (≥ +1 000 ₽ и ≥ +25%).
- **Регулярные платежи**: ≥ 3 платежа одному мерчанту за 13 месяцев, медиана
  интервалов 5–9 / 25–36 / 340–390 дней, ≥ 60% интервалов в пределах ±25%.
  Подписка: известный сервис из каталога или ежемесячно со стабильной суммой
  (CV < 8%). Отклонённая подсказка возвращается только после ≥ 3 новых платежей.
- **Аномалии**: сумма > max(3 × медиана, медиана + 4·MAD) категории за 6
  прошлых месяцев (≥ 5 точек), ≥ 1 000 ₽; у нового мерчанта — «незапланированная».
- **Темп трат**: повседневные траты (без регулярных платежей и аномалий) /
  прошедшие дни, смешанные с прошлыми периодами (вес текущего растёт к концу
  месяца). Без истории — нужна неделя и ≥ 5 трат.
- **Прогноз**: расходы = потрачено + темп × оставшиеся дни + предстоящие
  обязательные; доходы = получено + регулярные доходы, не ниже медианы трёх
  прошлых периодов, если доход был в каждом; баланс к концу периода.
  Оценки округляются до рубля.
- **Свободный остаток**: баланс + ожидаемые регулярные доходы − обязательные
  платежи до конца периода (и ещё минус ожидаемые повседневные траты).
- **Риск бюджета**: прогноз траты по бюджету + нормальная аппроксимация
  разброса дневных трат → вероятность превышения и сумма превышения.
- **Паттерны**: рост/снижение 3 месяца подряд (≥ 15% и ≥ 1 000 ₽),
  стабильность дохода по CV (< 15% стабильно, < 40% умеренно), необычные
  месяцы (z ≥ 2 при ≥ 6 месяцах), сезонность (тот же месяц год назад ≥ 1,5 ×
  среднего), привычки (день недели, топ мерчантов).
- **Рекомендации**: бюджет = медиана 2–3 полных периодов, округлённая вверх
  до 500 ₽ (только где ≥ 2 000 ₽/мес и бюджета нет); цели — `savingsPace`.

Анализ идёт в базовой валюте; операции в других валютах исключаются (без
курса их нельзя честно складывать).

## 4. Персональная память

Файл `finora_ai_memory.json` в каталоге приложения (не входит в бэкапы и
импорт ledger). Хранит только сигналы пользователя:

- мерчант → категория с весами (сохранение = 1, исправление = 3, старый
  выбор теряет 2) и временем последнего голоса;
- история исправлений (последние 300);
- отклонённые подсказки (`subscription:`, `recurring:`, `budget:`, с
  «доказательством» — числом платежей на момент отказа);
- подтверждённые подписки и регулярные платежи.

Типичные суммы, дни и диапазоны **не хранятся** — они пересчитываются из
операций, поэтому память не расходится с данными. Тяжёлого переобучения на
телефоне нет: персонализация — это память поверх общей модели.

## 5. Классификатор

Ступени по доверию, оценки по одной категории объединяются (noisy-or):
память → история мерчанта → каталог (`ReceiptParser.suggestCategory`) →
локальная модель. Ниже 45% — «Я пока не могу уверенно определить категорию».
Результат: лучшая категория, уверенность, топ-3, источник, версия модели.

## 6. Локальная ML-модель

- `tool/finora_ai/features.py` ⇄ `inference/features.dart` — одинаковые
  признаки: нормализация, символьные 3-граммы мерчанта, слова, тип операции,
  ⌊log₂⌋ суммы, день недели, месяц, тип счёта; хеширование FNV-1a в 8192
  корзины, вес 1/√n.
- `tool/finora_ai/dataset.py` — формат CSV (`merchant, description,
  amount_minor, kind, account_type, date, label`), 28 канонических классов,
  синтетический набор из каталогов приложения + словари для классов без
  каталога, банковский шум, транслит, MCC-подобные описания; балансировка
  классов.
- `tool/finora_ai/train.py` — softmax-регрессия, mini-batch Adam + L2,
  экспорт `assets/ai/finora_classifier.json` (int8-веса + масштаб на класс,
  ~300 КБ), `tool/finora_ai/metrics.json`, фикстуры совместимости
  `test/fixtures/finora_ai_parity.json`.

```
python3 tool/finora_ai/train.py --version 1.0.0 [--extra размеченные.csv]
```

Версия модели хранится в файле (`version`, `created`, `format`) и
возвращается в каждом результате классификации.

**Честные метрики v1.0.0** — проверка на магазинах, которых модель не видела
при обучении (15% названий отложены целиком): accuracy 0,66, top-3 0,78,
macro-F1 0,60. На знакомых названиях точность почти полная, но это не
показатель. Поэтому в гибридной схеме модель — последняя ступень после памяти,
истории и каталога. Качество вырастет на реальных размеченных данных
(`--extra`).

## 7. Тесты

- `test/finora_ai_test.dart` — движки на управляемых данных (драйверы роста,
  подписка Spotify, повторное появление отклонённой подписки, аномалия,
  свободный остаток и прогноз, риск бюджета, рекомендация бюджета,
  «недостаточно данных»); слой ответов цитирует только числа движков;
  классификатор (память важнее каталога, исправление важнее сохранений,
  «не уверена», модель); совпадение Dart и Python на фикстурах; память
  сохраняется и читается; разбор вопросов.
- `test/finora_ai_screen_test.dart` — экран открывается, прогноз и инсайты
  видны, быстрый вопрос получает ответ.

## 8. Ограничения и следующие шаги

- Модель обучена на синтетике из каталогов; нужен реальный размеченный набор.
- Разные валюты не сводятся (нужен источник курсов).
- Подтверждённая подписка пока не превращается в «Платёж» автоматически —
  кнопка «создать регулярный платёж» из подсказки.
- Точные финансовые ответы остаются шаблонами движков. Необязательная
  экспериментальная Qwen для разговора и понимания намерений описана ниже.
