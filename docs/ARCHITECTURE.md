# Архитектура Finora

Поток данных: Flutter screen → FinanceController → FinanceRepository → SQLite. Проверки и расчёты вынесены в FinanceEngine и валидацию repository; виджеты не служат источником финансовых данных.

```
lib/
  main.dart                      загрузка, темы, навигация, блокировка всех маршрутов
  domain/
    models.dart                  неизменяемые модели, JSON-контракты
    finance_engine.dart          деньги, балансы, периоды, бюджеты, повторения
  data/
    finance_repository.dart      схема SQLite, atomic save/import, резервные копии
    demo_data.dart               демонстрационный семейный профиль
  services/
    security_service.dart        Android encrypted storage, PIN, биометрия
    notification_service.dart    разрешения, timezone, планирование уведомлений
  presentation/
    controller.dart              ChangeNotifier, последовательная очередь записей
    theme/app_theme.dart         цвета, шрифты, интервалы, темы компонентов
    widgets/                     карточки, операции, графики, цифровая панель
    screens/                     дашборд, операции, аналитика и management features
```

## Модель данных

Account, FinanceEntry, Category, Budget, Goal, RecurringRule, Member, AppPreferences — типизированные модели. Пользователь/семья представлены локальными Member, без серверной регистрации.

Таблицы SQLite: `currencies`, `members`, `accounts`, `categories`, `subcategories`, `entries`, `tags`, `entry_tags`, `attachments`, `budgets`, `goals`, `recurring`, `settings`. Включены foreign keys и индексы дат/категорий/счетов. Схема version1; при будущем изменении структуры требуется явная миграция.

Запись приложения проходит очередь контроллера и транзакцию базы. Импорт, восстановление и очистка демоданных используют ту же очередь, чтобы незавершённая запись не перезаписала восстановленные данные. Ошибка уведомлений после успешного commit не откатывает и не маскирует финансовую запись.

Repository сейчас атомарно записывает согласованное состояние целиком. Для очень больших историй нужны измерения и переход на инкрементальные записи, не меняя публичные финансовые инварианты. Не заявляется производительность на сотнях тысяч операций без профилирования.

## Инварианты

- Суммы — целое число минимальных денежных единиц с проверкой диапазона. Форматирование полных сумм и полей ввода также обходится без преобразования в double; double допустим только для геометрии диаграмм/процентов.
- Доход/расход связан с категорией соответствующего типа и существующим счётом той же валюты.
- Перевод имеет разные существующие счета и две суммы при разных валютах. Категории дохода/расхода у перевода нет.
- Pending/cancelled не входят в баланс, статистику и бюджеты. Периоды `[start,end)`.
- Финансовый месяц начинается в настраиваемый день1–28. Бюджеты относятся к текущему такому месяцу.
- Месячное/годовое повторение хранит `anchorDay`: 30янв→28фев→30мар, 31янв→28фев→31мар.
- Автоматическое создание идемпотентно: идентификатор операции содержит правило и дату наступления; одна запись не создаётся повторно при повторном открытии.
- Удаление связанного счёта/категории/участника запрещено. Счёт с историей можно архивировать; категории операций можно изменить в редакторе.

## Восстановление и будущая синхронизация

JSON имеет versioned envelope, проверку типов, ссылок, уникальности идентификаторов, денежных диапазонов и ограничений размеров. Внешние пути к вложениям не доверяются; встроенные данные чеков восстанавливаются в управляемый каталог приложения. Все проверки выполняются до замены финансового состояния.

У моделей стабильные UUID; repository является границей для будущего sync-adapter. Перед реализацией cloud sync понадобятся серверная авторизация, шифрование транспорта, tombstones, журнал изменений и стратегия конфликтов. Эти возможности не имитируются локальными переключателями.

## Визуальная система

Графит/молочный фон, четыре выбираемых акцента, скругления16–28, outline-иконки единого набора, типографическая иерархия и карточки разных размеров. Графики рисуются локально CustomPainter без сетевых ресурсов. Поддерживаются system/light/dark; системный масштаб текста сохраняется.
